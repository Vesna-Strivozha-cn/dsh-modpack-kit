# dsh-modpack-kit（DSH 也要整合包）

把多个 DSH 插件打成一个 `.dshpack`，一次装好。换台机器、少个插件、版本对不上时，不用再一个个搜、一个个装；对方机器上只剩一个 DSH 本体也能装——包里自带独立安装器。

- **两种包**：完整版自带插件本体（对方没装本插件，照包内 `README.txt` 手工也能装）；轻量版只记名字与版本，安装时按记录取包，体积小。两种包都附一个**独立安装器** `install/`，一台只剩 DSH 本体的机器也能装。
- **逐插件模式**：每个插件单独选「基础配置」（上游原版 + 默认配置）或「本地改动」（你本机的代码、配置、数据快照）。
- **安全**：打包前**强制**检测敏感信息与风险代码，命中只留掩码、原文不落盘；高风险一律先停下来，确认（「我知道在干什么」）才出包；安装前再校验 sha256 完整性、兼容性与许可证。它不替代杀毒软件，也不证明某个插件安全。
- **装完能收尾**：按条目回填包内配置（只动目标那条），可选「装好先不启用」（只装文件、不登记 bundle）或「装完直接启用」，两个方向都由你定。
- **跟插件市场同源**：分类是市场那 23 个分区，首屏只列你已装的，搜索与分页走市场目录；同名插件行末有「（切换市场版）」。
- **三处入口**：设置页、侧边栏、插件页内各一个独立开关，改完立即生效；至少留一处，最后一个不能再关。

> **建议先装插件市场（`dshmarket`）再用它，但不是必须。** 不装也能打包、装包、检测、回填配置；差别只在「发现类」能力（分类胶囊、搜索、市场版版本对比、切换市场版、轻量包按版本取包），详见下面「与插件市场：联动，以及没有它时差在哪」。

## 安装

在已装 DSH 的机器上：

```bash
dsh plugin --profile desktop add dsh-modpack-kit
```

或本地开发目录（本项目就在 `D:\桌面\蛆\整合包`）：

```bash
dsh plugin --profile desktop add "file:D:/桌面/蛆/整合包"
```

装完重启 DSH，左侧栏出现「整合包」。

## 与插件市场：联动，以及没有它时差在哪

**建议先装插件市场（`dshmarket`），但本插件不依赖它。** 装不装都能用，区别只落在「发现与取包」这一层。

**联动的地方**
- 目录同源：直接读插件市场自己的目录包 `dsh-plugin-catalog`（先走 CDN 的 `index.json`，取不到退回 npm tarball），23 个分区、条目数、排序规则都跟市场一致；市场没装也能用，只是少了它的界面。
- 安装同路：都走 `dsh plugin --profile <p> add`，两边装的插件互相可见，不需要各记一份状态。
- 已装插件会用目录补齐描述与分区，标出「市场版 vX」以及是否有更新；同名条目行末出现「（切换市场版）」。
- 三处入口里「插件页内」那一栏，跟市场的 Discover 栏并排，互不占位。

**有市场 / 没市场对照**

| 能力 | 装了插件市场 | 没装插件市场 |
| --- | --- | --- |
| 打包（完整版 / 轻量版）、强制安全检测 | ✅ | ✅ 完全一样，全在本地跑 |
| 装包、完整性校验、兼容检测、许可证检查 | ✅ | ✅ 一样 |
| 配置回填、装好先不启用 | ✅ | ✅ 一样 |
| 侧边栏 / 设置里 / 插件页内三处入口 | ✅ | ✅ 一样（这些槽位是 DSH 核心声明的，不是市场插件） |
| 分类胶囊、搜索、服务端分页 | ✅ | ✅ 只要建过一次目录索引就行（5~30 秒，看网络） |
| 已装插件补齐描述、分区、市场版版本 | ✅ | ✅ 建过索引后一样 |
| 「（切换市场版）」按上游原版打包 | ✅ | ✅ 建过索引后一样 |
| 轻量包安装时按版本取包 | ✅ | ✅ 只要有 npm registry 网络 |
| 市场 Discover 栏、市场自己的更新入口 | ✅ | ❌ 没有（用本插件或 `dsh plugin` 装同一个包即可） |

**没索引、也没网时会怎样**（这种情况页面会明说，不会静默装错）
- 首屏照旧只列本机已装插件，打包与安装不受影响。
- 分类胶囊只剩「全部」，已装行的分类退回内置兜底规则，与市场 23 类的 id 不完全对得上——按 theme / memory 之类筛会漏几条。点「建立目录索引」跑一次就恢复。
- 搜索、市场版版本对比、「（切换市场版）」按钮不出来。
- 轻量包装不了（它不带源码，必须联网按清单里的版本取包）；完整版照装。

## 分类、搜索与分页

- 分类就是插件市场的 23 个分区（全部 / AGI 架构探索 / UI 增强 / 用量与计费 / 主题与外观 / 模型与账号接入 / 身份与通信 / 会话与消息 / 记忆 / 工具与能力 / WSL 与 Windows 互操作 / 浏览器与网页 / 视觉与多模态 / 语音与音频 / 文档与渲染 / 技能包 / 工作流与自动化 / Git 与代码评审 / 通知与集成 / 开发与运行时 / 安全与权限 / 远程与移动端 / 插件市场与管理 / 娱乐），名字和条目数都从市场目录里读。
- **首屏只列本机已装的插件**，不联网、不卡顿。搜索框右侧提供「全部加入」（一次选中本机已装全部插件，均按「基础配置」）与「清除选择」。输入关键词或点分类才去目录里搜，结果是服务端分页，一页 20 条（设置里可改），底部「加载更多」再取下一页。
- 排序照抄市场的规则：**已装优先**，再按相关度（整字段命中 > 包含 > 其它词；包名权重最高，其次所有者、仓库，描述与分类最低），同分保持目录原序。本机独有、目录里没有的插件也能被搜到。
- 本机已装的插件如果目录里有同名条目，行末会有小字「（切换市场版）」：点一下改用上游原版代码 + 默认配置打包，装出来和你从插件市场装一样；再点一次「（切回本机版）」回到本机快照。同名不代表一定是同一个插件，所以它只是**选项**，默认仍打本机那份。

## 显示位置（三处独立开关）

设置页底部三个开关，各自独立，改了立刻生效，不用重启：

| 开关 | 显示在哪 |
|---|---|
| 在设置里显示 | 设置页内一栏「整合包」（含插件的插件设置 tab） |
| 在侧边栏显示 | 左侧栏「整合包」入口 |
| 在插件页内显示 | 插件的插件页里，跟插件市场同一位置，单开一栏「整合包」 |

三个全关会被拒绝（`POST /settings` 返回 400）——否则就再没有入口能把它关回来了；只关侧边栏是允许的，那时从设置页进。

## 逐插件：基础配置 / 本地改动

打包时每个插件可以单独选：

- **基础配置**：上游原版代码 + 插件默认配置，不带你的改动（会按版本从 registry 重下并校验 sha512）。
- **本地改动**：你本机现在的代码、配置条目、数据快照一起打进去。

选中某个插件后，行内才会出现「基础配置 / 本地改动」两个按钮，默认是「基础配置」；结果里会标明每个插件实际用了哪种。搜索框右侧另有「全部加入」（把本机已装的全部插件一次加入选择）与「清除选择」。

## 两种包

| 版本 | 内容 | 适用 |
| --- | --- | --- |
| 完整版 `full` | 清单 + 插件文件 + 配置 + 检测报告 | 对方没装本插件也能按 README 手工装；离线可用 |
| 轻量版 `lite` | 清单 + 配置 + 检测报告 | 体积小，安装时联网按版本取包 |

两者都带 `integrity.json`（sha256）、`security/report.txt` 与不依赖本插件的手工安装说明。

两种包都额外带一个独立安装器 `install/`（`install.mjs` + Windows 的 `install.cmd` + shell 的 `install.sh`），所以**一台干净到只剩 DSH 本体的机器也能装**：

```bash
# 解压后进包目录，任选其一
./install.sh                      # 或双击 install.cmd（Windows）
node install/install.mjs --profile desktop
node install/install.mjs --profile desktop --dry-run      # 只看要做什么
node install/install.mjs --profile desktop --no-bundles   # 装文件但不启用
node install/install.mjs --dsh "D:/某处/DeepSeek Harness.exe"  # 自带 dsh 路径
```

安装器只依赖 node 与 dsh 命令：先找 `--dsh`/`DSH_CLI`，再找 PATH 里的 `dsh`，最后试常见安装路径；完整版会先把插件复制到 `~/.dsh/dsh-modpack/vendor/<包名>-<短hash>/` 再装（这样解压目录删了也不会断），轻量版按 `name@version` 从 npm 取。装完把 `configs/` 里的条目并进 profile 的 `cordis.patch.yml`，最后提示重启 DSH。它不会自动执行任何包里带的脚本。

目标目录固定是本机的 `~/.dsh`：DSH 的命令行只认自己的家目录（实测不认 `DSH_HOME` / `USERPROFILE`），安装器不去猜别的位置。`--profile` 写一个没建过的名字也行，DSH 会在第一次装插件时自动初始化它。

## 开发

```bash
EXE="/d/大肥鱼/DeepSeek Harness.exe"
# 单测 / 宿主路由 / 联网烟测
ELECTRON_RUN_AS_NODE=1 "$EXE" test/run.mjs
ELECTRON_RUN_AS_NODE=1 "$EXE" test/host-smoke.mjs
ELECTRON_RUN_AS_NODE=1 "$EXE" test/live.mjs
# 改完源码：同步到 profile 副本（file: 依赖是硬链接拷贝，cp 会 EBUSY）并校验
ELECTRON_RUN_AS_NODE=1 "$EXE" dev/tools/sync.cjs
ELECTRON_RUN_AS_NODE=1 "$EXE" dev/tools/verify.cjs
```

本机没有独立的 node：用 `ELECTRON_RUN_AS_NODE=1` 借 DSH 自带的 Node 跑脚本。

`dev/tools/sandbox-e2e.mjs` 是端到端演练：从本机挑一个真插件打成包 → 读回校验 → 装进临时 profile `modpack-sandbox-tmp`（先不启用）→ 断言依赖写入、`bundles` 仍为空、desktop profile 一字未动 → 最后删掉临时 profile 与临时目录。它不碰你的 desktop profile。

`dev/tools/e2e-suite.mjs` 是整套流程自测：随机挑本机 3 个插件（`SEED=xxx` 可复现）→ 打包 full（混合「基础配置 / 本地改动」）→ 读回校验清单与完整性 → 篡改一个载荷确认会被抓住 → 「有插件」路线用 `installPack` 装进临时 profile → 「无插件」路线解压后跑包内独立安装器（`--no-bundles`）→ 轻量版按版本从 registry 取包再装 → 最后清理 3 个临时 profile、vendor 新目录与临时目录，并用 sha256 确认 desktop 的 `package.json` 与 `cordis.patch.yml` 一字未动。

`dev/tools/risk-e2e.mjs` 专测风险流程：市场查不到的高危包停在 `paused` 可删可确认、市场收录的高危包确认后在同一任务里续跑出包。

`dev/dsh-refs/` 是官方插件文档的本地参考副本，不参与发布（`files` 里没有 `dev`）。`dev/tools/check-categories.mjs` 只读核对分类分布与「哪些已装插件在市场里有同名条目」。

## 安全检测

- **打包前是强制的，关不掉**：设置与包选项里的开关照常显示，但点它只会弹一行红字「你想干什么」，五秒后自动消失；就算直接调 API 写 `scanBeforePack: false`，服务端也会拉回 `true`，`buildPack` 里根本没有不扫的分支。
- 安装前各一次，静态读文本，不执行任何代码（安装前扫描仍可在设置里关，但默认开）。
- 规则覆盖：私钥、云厂商/代码托管 token、模型 key、Cookie 与会话字段、邮箱/手机号/身份证、内网 IP、本机路径；`curl|sh`、`powershell -enc`、`eval`、可疑长 base64、关闭证书校验、安装脚本等。
- 命中原文不落盘：报告只留规则名、文件、行号与掩码；同一文件同一行同一规则只记一条（一个文件里反复出现的 `exec(` 不会刷成几十行）。
- **高风险一律先停下来等确认**：不论插件能否在本地市场目录里查到，检出高危都停在「等决定」，打包页下方按插件列出命中项；点「我知道在干什么」会在**同一个任务里从检测点接着跑完**（不重新收集、不重复扫描），确认状态写进清单 `security.acknowledged`。不想继续就删掉那条记录，不会在本地留下半成品。
- 目录里能查到的插件，提示语会说明「这批风险来自市场已收录的发行包」；查不到的会提示「这是本机插件，市场里没有对应条目，请自己确认来源」——区别只在措辞与清单里的来源标注，出口是同一条路。
- 轻量包在「下载完、真正安装前」还会对本机刚取下来的代码补扫一遍，高危同样阻断（不是只信清单里那份报告）。
- 包内 `integrity.json` 缺失或清单对不上，一律阻断（要显式 `force`）。
- 解压有体积、压缩比与条目数上限，解压时还按声明长度卡输出（防 zip bomb），拒绝路径逃逸、符号链接、加密条目。
- 只允许 https 与白名单域名下载，逐跳校验重定向。
- 命中按来源分栏：每个插件一组、配置快照一组、数据快照一组，整合包自身的清单与安装器单独一组；整个列表可折叠，每一组也能单独折叠，带高/中/低计数（高危的组排在最前）。

## 打没装的插件

搜索框在插件市场目录里查到的条目，**本机没装也能直接勾选打包**：这类条目打的是「市场来源」——打包时按版本从 registry 取包（默认取那一条的当前版本，想钉别的版本就在版本框里写），包内清单记 `source: "npm"`，安装时同样从市场按版本下载。

- 「本机 / 市场 · 未装」标签区分来源；已装的行才有「基础配置 / 本地改动」与「（切换市场版）」。
- 没装的插件没有本机代码可打，所以永远是「基础配置」语义（上游原版 + 插件默认配置）。
- 许可证仍按允许列表校验：市场条目的 license 不在列表里时，需要勾「我确认……有权再分发」才会出包。

## 用「打开文件」的方式挑包，或自己挑目录

安装页不再只认插件自己的 `packs` 目录，也不用先知道路径：

- **选择文件…**：安装页有「选择文件…」按钮，弹系统文件选择器（只列 `.dshpack`），选中即读取。
- **浏览文件夹…**：目录那一行有「浏览文件夹…」按钮，弹系统目录选择器；选完目录会自动列目录内容，再勾文件即可。也可以直接在输入框里手写路径，两种方式并存。
- **自己挑目录**：填任意目录（例如桌面、下载目录）后点「读这个目录」，列出该目录下的 `.dshpack`；选中后按绝对路径读取。点「回到默认」回到插件自己的 `packs`。
- **已导入的整合包**：用文件选择器或上面的方式读过的包，会留在「已导入的整合包」列表里（最多 8 份同时保留），每张卡片写着打包时的名字、作者、生成时间和描述，可以直接点「选择」切到那一份，或「移除」。列表在内存里，退出程序就清空。
- 读取走的是 `POST /pack/drop`：默认发原始字节（上限 256 MB）；某些环境不允许带二进制的 POST，界面会自动退回 base64 的 JSON 重发一次，服务端两种都收。目录列举走 `POST /packs { dir }`。两者都不写入磁盘，只有你点「安装」才会碰 profile。
- 拖拽已经去掉（外壳自己会接管文件拖放，容易两边都读不到）。

## 安装：也走进度、已装的先跳过、装完再决定换不换

安装现在和打包共用左下角那个进度窗：读包 → 校验完整性 → 扫描 → 逐插件装 → 登记启用清单 → 回填配置，百分比一路走完；任务同样能终止，也能和打包同时跑。

**本机已经装过的插件会先跳过。** 判定按插件名，不按版本——同名的、以及同一个插件但版本不同的，都算「已有」；其余插件照常装完。装完后界面上会列出这些被跳过的插件（本机版本 → 包内版本），给两个选择：

- 直接完成：保留本机那几份，什么都不覆盖；
- 替换为包内版本：只把列出来的那几个换成包内版本（没列出来的不动）。

轻量包（不含插件本体）走的是同一条路：打开时先从 registry 按版本取包，再按上面的规则装。

**联网且插件市场有同名条目时，优先按市场版本装。** 这是安装页上的一个开关（默认开，对应设置项 `preferMarketOnInstall`）：能查到就装 `名字@版本`，装的时候那份代码来自 registry；查不到、离线、或者你把开关关掉，就按包内带来的那份装。每个插件的动作里都会写明这一条走的是 `market` 还是 `pack`。

**裸 DSH 那一侧**（包里自带的独立安装器）同样默认跳过已装的插件：装的时候它会依次打印「跳过 xxx：本机已装 y」，装完再汇总列出「以下 N 个插件本机已经装了……要换成包内版本，重跑并加 --replace」：

```bash
node install/install.mjs --profile desktop              # 跳过已装的，其余照装
node install/install.mjs --profile desktop --replace    # 本机已装的也换成包内版本
```

## 打包进度与并发

点「打包」后不会卡住页面：任务转到界面的**悬浮窗**（默认在右下角），同一行显示当前在做什么（收集文件 / 读取插件 / 抓配置快照 / 安全检测 / 写入清单 / 压缩）与百分比，下面是进度条。点开悬浮窗能看到每个任务各占一行（标签、状态、进度条），进行中的任务带「终止」按钮；终止只在内存里停下，**不会在本地留下半成品文件**。

任务在安全检测那一步撞到高风险时，会停在「等决定」，并且**打包页下方按插件分别列出命中项**（每个插件一组：文件名、行号、规则名、级别；高/中/低计数）。那一组里有「我知道在干什么」——点它就忽略这批风险，在**同一个任务里从检测点接着跑完**：进度不回退、不重新收集文件，也**不会把这个任务再扫一遍**，清单里记为 `acknowledged`，红字警告随之撤掉（同一条记录往后只显示状态与进度）。市场收录的和本机自己的插件都走这条路，只是提示措辞会说明风险来自哪儿。不点它的话，任务就停在原处等你处置，记录可以删掉。已经收尾的任务右侧会出现「删除该进程」，把这条记录从列表里抹掉；跑着的任务只有「终止」，删不掉。窗口标题栏右侧还有「清空进程」，一次清掉所有收尾记录——完成的、失败的、取消的，连同「超过打包上限」这类中途报错卡住的一起带走；还在跑的、停在风险点等你决定的会留着。失败的那一行会把原因写红字显示出来，方便你判断是哪个插件体积太大。清空后，打包页上那条失败提示也会一起消失（不会留下来当幽灵）。如果点了没反应，多半是宿主还是旧代码，界面会自动改成逐条删除。安装任务不用你手动清：结果写进安装页之后，它会自己从进度窗里摘掉。「异常的自己走」是硬规矩——失败和取消的记录只留十几秒，完成的按设置 `jobKeepSeconds`（默认 60 秒）清掉，卡住的 running（十分钟没有新进度）会被判成失败再一起收走；只有正在跑的、停在风险点等你决定的会一直留着，并且照常显示进度。点「清空进程」时界面先立刻把那些行摘掉，再通知服务端删，所以不会出现「点了没动静」。标题栏上的「清空进程」与「收起」不再和拖动、展开抢同一块区域：按在这两个按钮上只算点击，不会触发拖动，也不会顺手把窗口展开或收起。

打包**完成**后，记录上不是「终止」而是「下载安装包」：点它就切回打包页、滚到那次的结果与下载按钮（也可以在结果里选择存到本机 packs 目录）。打包结果本身放在界面进程的内存里，**切页签、关掉面板再回来都还在**，留到退出程序为止——插件被关掉或程序退出才清。

悬浮窗**按住标题就能拖到任意位置**，松手记住，下次打开还在那儿（存在浏览器本地，和服务端设置无关）；拖到哪都会被限制在窗口内，不会丢到屏幕外。

没有任务时它自己收起，只在原来那个位置留一枚「进度」小按钮；点它就把窗口唤出来。有任务开跑时会自动冒出来，手动「收起」过也会被重新放出来。

打包期间可以继续选插件、改选项、再打一个包——多个任务并行跑，各自独立，互不影响。

体积上限默认 **512 MB**（设置里可改）：这是打包结果的上限；单个下载（一个 tarball 或一份目录索引）另有更紧的 256 MB 上限，避免一次吞下过大的文件。

## 安装与「先不启用」

- 安装走官方 `dsh plugin add`（和插件市场同一条链路）：优先直接起宿主 exe + 内置 `cli.js`，参数不经 `cmd`，所以中文用户名、带空格路径都不会被引号吃掉；找不到才退回 `.cmd`。
- 勾「装好先不启用」时，插件文件与依赖照装，但装完会把 `dsh.profile.bundles` 精确撤回原样 —— 重启也不会加载，想启用再手动加回来。
- 解包前会先清掉 `vendor/<包>/` 里的旧目录，避免上一版残留文件混进新版本。

**它不是杀毒软件**：静态检测会漏也会误报，装第三方插件前仍应自己看来源。

## 配置同步

包内 `configs/<name>.json` 保存打包时 profile 补丁层里的条目。安装时按条目 `upsert` 回 `cordis.patch.yml`：只动目标插件那一条，其它字节保留；已有本地配置且开启「保留本地修改」时跳过。

## 二次开发

- `lib/` 下每个模块都可单独 import：`zip`/`tar` 是通用读写器，`scan` 可接 `extraRules`，`yamlish` 只服务 `cordis.patch.yml`。
- 清单里的 `extensions` 字段打包时原样写入、安装时原样保留，可放自定义数据。
- 设置项 `extraScanRules` 会把额外规则并进扫描器。
- 页面只消费 `/dsh-modpack-kit/api/*`，换 UI 不必改后端。
