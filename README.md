# 整合包（dsh-modpack-kit）

> 谁说dsh不能整整合包呢？（你说这几个插件整一块不牛逼坏了）
>
> npm：https://www.npmjs.com/package/dsh-modpack-kit

为 DeepSeek Harness 提供类似 HMCL / PCL 这类「我的世界启动器」的整合包打包与安装能力：把多个插件连同各自的配置与数据打成一个 `.dshpack`，一次安装到位。

常见叫法与搜索词：整合包、插件打包、一键安装、批量安装、离线安装、迁移插件、备份插件配置、modpack、plugin bundle。

- **三种打包策略**：完整包自带插件本体（不联网也能装，有网时按市场版本装、装完是市场版）；仅下载码只记 `名字@版本`（体积最小，安装时联网取包）；混合包以轻量为主——能按版本装的只记版本，没有确定版本或要带走本机改动的插件连本体一起打进来（这部分不用联网），配置/数据/补丁片段照样带。三种都附独立安装器，纯净版 DSH 都能装。
- **逐插件定制**：每个插件单独选「插件预设」（只带插件默认配置）或「自定义配置」（本机的配置条目与数据快照，本机来源的还带代码改动），同一个整合包里可以混用。
- **只列真正的插件**：一个插件自带内部组件时（例如壁纸引擎把组件发成了独立包），只列父包，内部组件随父包一起安装，不会被重复打包或重复安装。
- **配置与数据保真**：配置按原结构回填到 `cordis.patch.yml`，只改目标条目、其它字节保留；数据快照写回 `~/.dsh/<目录>/`，默认不覆盖本机已有文件。疑似凭据替换为 `${REDACTED}`，其余自定义项原样保留。
- **打包前强制检测**：对敏感信息与风险代码做静态扫描，命中只留掩码、原文不落盘；高风险停在「等决定」，确认后在同一任务里从检测点续跑。安装前再校验 sha256 完整性、兼容性与许可证。
- **与插件市场同步版本**：分类、搜索、分页与条目来自市场目录（首屏只列已安装插件）；本机插件若在市场有同名条目，可切换市场版本打包，联网安装时也可优先按市场版本取包。
- **三处入口**：设置页、侧边栏、插件页内各一个独立开关，改动即时生效；至少保留一处，最后一个不可关闭。

> 建议先安装插件市场（`dshmarket`）以启用完整的发现能力，但不是必须：不装也能打包、装包、检测与回填配置，差别见下文「与插件市场：联动，以及没有它时差在哪」。
>
> 项目地址：<https://github.com/Vesna-Strivozha-cn/dsh-modpack-kit> —— 如果它省了时间，欢迎在仓库点个 Star。

## 安装

在已装 DSH 的机器上：

```bash
dsh plugin --profile desktop add dsh-modpack-kit
```

也可以从 GitHub 直接装（不经过 npm）：

```bash
dsh plugin --profile desktop add github:Vesna-Strivozha-cn/dsh-modpack-kit
```

装完重启 DSH，左侧栏出现「整合包」。

## 与插件市场：联动，以及没有它时差在哪

**建议先装插件市场（`dshmarket`），但本插件不依赖它。** 装不装都能用，区别只落在「发现与取包」这一层。

**联动的地方**
- 目录同源：直接读插件市场自己的目录包 `dsh-plugin-catalog`（先走 CDN 的 `index.json`，取不到退回 npm tarball），23 个分区、条目数、排序规则都跟市场一致；市场没装也能用，只是少了它的界面。
- 安装同路：都走 `dsh plugin --profile <p> add`，两边装的插件互相可见，不需要各记一份状态。
- 已装插件会用目录补齐描述与分区，标出「市场版 vX」以及是否有更新；同名条目标为「本机 · 有市场版」，勾选时默认按市场版打包，行末可用「（切回本机版）」改回本机那份。
- 三处入口里「插件页内」那一栏，跟市场的 Discover 栏并排，互不占位。
- AI 搜索同源（0.2.1 起）：搜索框的「AI 搜索」直接调用插件市场新版本的 `POST /dsh-market/ai-search`，用的是同一套目录、同一个模型配置，不在本插件里另存模型与 Key；市场是旧版就没有这个开关。**AI 搜索花的 token 记在插件市场那边**——它用你在「设置 → 模型」里配的模型发请求、扣你的额度，本插件只转发问题与结果。
- 分组同源：直接读市场存在 profile 下的 `.dsh-market/state.json`（只读），把「已装」按你的分组折叠展示，组头带「一键加入」「清空本组」。
- 装完的身份：插件市场只看 profile 里的依赖写法——`file:`/`link:` 就是「本地」，semver 才是市场版。所以从市场取的插件一律按 `name@version` 装（清单里带版本号就不再问 registry），轻量包下载完也按版本装；只有确实拿不到市场版、退回包内副本时才会写成 `file:`，安装结果里会明确提示「插件市场会把它显示成本地安装」。
- 市场侧栏那一行（关的是市场自己的，不是整合包的）：设置里有「强制关闭插件市场在侧栏里的那一行（只关市场自己的，不动整合包）」开关，开关就在设置上一栏「显示位置」里（和整合包那三处入口挨着）、打开就替市场写 `POST /dsh-market/sidebar-entry { enabled: false }`（它自己的偏好存在 `<profile>/.dsh-market/state.json`，我们只改这一个键），每次开机再确认一次；关掉开关就还回去。

**有市场 / 没市场对照**

| 能力 | 装了插件市场 | 没装插件市场 |
| --- | --- | --- |
| 打包（完整版 / 轻量版）、强制安全检测 | ✅ | ✅ 完全一样，全在本地跑 |
| 装包、完整性校验、兼容检测、许可证检查 | ✅ | ✅ 一样 |
| 配置回填、装好先不启用 | ✅ | ✅ 一样 |
| 侧边栏 / 设置里 / 插件页内三处入口 | ✅ | ✅ 一样（这些槽位是 DSH 核心声明的，不是市场插件） |
| 分类胶囊、搜索、服务端分页 | ✅ | ✅ 只要建过一次目录索引就行（5~30 秒，看网络） |
| 已装插件补齐描述、分区、市场版版本 | ✅ | ✅ 建过索引后一样 |
| AI 搜索（按一句话让模型从目录里挑插件） | ✅ 需较新版市场，用它自己的模型与 Key | ❌ 没有，只做关键词搜索 |
| 按市场分组折叠展示、一键加入整组 | ✅ | ❌ 平铺列表（分组状态在市场那边） |
| 有市场版时默认按上游原版打包 | ✅ | ✅ 建过索引后一样 |
| 轻量包安装时按版本取包 | ✅ | ✅ 只要有 npm registry 网络 |
| 市场 Discover 栏、市场自己的更新入口 | ✅ | ❌ 没有（用本插件或 `dsh plugin` 装同一个包即可） |
| 关掉插件市场自己那一行侧栏入口（设置里一个开关） | ✅ 直接写它的 `sidebar-entry` | ❌ 没有那一行可关 |

**没索引、也没网时会怎样**（这种情况页面会明说，不会静默装错）
- 首屏照旧只列本机已装插件，打包与安装不受影响。
- 分类胶囊只剩「全部」，已装行的分类退回内置兜底规则，与市场 23 类的 id 不完全对得上——按 theme / memory 之类筛会漏几条。点「建立目录索引」跑一次就恢复。
- 搜索、市场版版本对比、市场版/本机版的切换按钮不出来（此时只能打包本机那份）。
- 「AI 搜索」开关也不会出现——它借的是插件市场新版本的接口，没有市场就没有。
- 轻量包装不了（它不带源码，必须联网按清单里的版本取包）；完整版照装。

## 和「解除卡顿」插件

本机装了插件市场的「解除卡顿」（`dsh-unlag`）时，页面顶部会多一个「解除卡顿」按钮：点一下就是让它整理一次（`POST /dsh-unlag/reload?requestId=…`，按它要求带 `x-dsh-unlag: 1`），结果显示在按钮旁边。鼠标悬浮能看见来源——「来自插件市场的 dsh-unlag@版本（不是本插件的功能）」。

没装就什么都不显示；它被关掉或接口换了也只是按钮报错，不影响打包与安装。

## 分类、搜索与分页

- 分类就是插件市场的 23 个分区（全部 / AGI 架构探索 / UI 增强 / 用量与计费 / 主题与外观 / 模型与账号接入 / 身份与通信 / 会话与消息 / 记忆 / 工具与能力 / WSL 与 Windows 互操作 / 浏览器与网页 / 视觉与多模态 / 语音与音频 / 文档与渲染 / 技能包 / 工作流与自动化 / Git 与代码评审 / 通知与集成 / 开发与运行时 / 安全与权限 / 远程与移动端 / 插件市场与管理 / 娱乐），名字和条目数都从市场目录里读。
- **首屏只列本机已装的插件**，不联网、不卡顿。搜索框右侧提供「全部加入」（一次选中本机已装全部插件，均按「自定义配置」）与「清除选择」。输入关键词或点分类才去目录里搜，结果是服务端分页，一页 20 条（设置里可改），底部「加载更多」再取下一页。
- 排序照抄市场的规则：**已装优先**，再按相关度（整字段命中 > 包含 > 其它词；包名权重最高，其次所有者、仓库，描述与分类最低），同分保持目录原序。本机独有、目录里没有的插件也能被搜到。
- 每行最前面有一个来源徽标，写着当前选的是「市场版」还是「本机版」（未勾选时显示「已装 / 市场未装」）。本机已装的插件如果在目录里有同名条目，行末会显示「改为市场版」：点一下改用上游版本，结果与从插件市场安装一致；再点「改为本机版」恢复本机快照。默认按市场版打包，避免把本地开发版带进包、装到别人机器上。同名可能只是撞名，改成「本机版」即按本机快照打包。

## 显示位置（三处独立开关）

设置页底部三个开关，各自独立，改了立刻生效，不用重启：

| 开关 | 显示在哪 |
|---|---|
| 在设置里显示 | 设置页内一栏「整合包」（含插件的插件设置 tab） |
| 在侧边栏显示 | 左侧栏「整合包」入口 |
| 在插件页内显示 | 插件的插件页里，跟插件市场同一位置，单开一栏「整合包」 |

三个全关会被拒绝（`POST /settings` 返回 400）——否则就再没有入口能把它关回来了；只关侧边栏是允许的，那时从设置页进。

## 分组：与插件市场同一套

插件市场的分组（profile 下 `.dsh-market/state.json` 里的 `groups` / `groupOrder`）会被原样读进来，用来整理「已装」这一屏：

- 分组标题一行：折叠箭头、组名、成员数、已选数；后面跟「一键加入」「清空本组」。
- 点标题上的箭头折叠或展开；展开后每个成员就是原来那一行，版本、来源徽标、「插件预设 / 自定义配置」、改为市场版都照旧可用。
- 不在任何分组里的插件收在最后「未分组」。
- 默认逻辑不变：分组不会自动勾选任何插件；「一键加入」只是替你把这一组的每一行按它自己的默认来源与「插件预设」勾上，之后仍可逐个改。
- 分组只是整理信息，不决定启用状态；市场没装、没建过分组、状态文件读不出来时，这一屏就是平铺列表。
- 按组打包会记住组名：在组头点「一键加入」后打出来的包，清单里每个成员带 `group`；装到**同样装了插件市场**的机器上时，会把这些插件并进同名分组（只加成员，不动对方已有的其它分组、顺序和停用名单）。目标机器没装市场时不写分组，安装结果里会说明一句。

## 逐插件：插件预设 / 自定义配置

打包时每个插件可以单独选：

- **插件预设**：只打插件默认配置，不带本机的配置条目与数据快照；代码按所选来源（本机快照或按版本从 registry 重新下载并校验 sha512）。
- **自定义配置**：带上本机这份插件的配置条目与数据快照；来源是本机时，代码改动也一起打包。

市场版与本机版都提供这两枚按钮：勾选任意插件后行内出现「插件预设 / 自定义配置」，默认是「插件预设」（优先插件自带的默认配置文件），要带本机配置与数据再点「自定义配置」；结果里会标明每个插件实际用了哪种。搜索框右侧另有「全部加入」（把本机已装的全部插件一次加入选择）与「清除选择」。

## 三种打包策略

打包界面这一栏叫「打包策略（必选）」，三块卡片按你勾的插件实时判定：

- 能选的正常显示；不能选的整块文字变灰、边框变虚线，右上角标「不可选」，鼠标移上去是禁止符号；
- 点灰掉的卡片不会切换策略，而是在下面弹出「为什么不能选」；
- 已经选了某个策略、之后又勾了让它不可用的插件，会提示「当前选的 X 现在不适用」并给出一键换成可用策略的按钮，打包按钮同时禁用，不会带着无效策略提交；
- 判定与打包共用同一段逻辑（服务端 `computePlan`），界面算的和真正打包时算的一致，服务端还会在打包请求里再拦一次。

| 策略 | 内容 | 体积 | 市场身份 | 适用 |
| --- | --- | --- | --- | --- |
| 完整包 `full` | 清单 + 插件本体 + 配置 + 数据快照 + 检测报告 | 最大（≈ 源码压缩后） | 有网按 `名字@版本` 装 → `^版本`，市场认市场版；离线退回包内副本 → 显示本地 | 目标机器没装本插件、或没网 |
| 仅下载码 `lite` | 清单 + 版本号 + 检测报告 | 最小（几个插件常常不到 1 MB） | 联网按版本装，市场版 | 大家在线的场合，只求快 |
| 混合包 `hybrid` | 清单 + 版本号 + 配置/数据/补丁片段 + 检测报告；没有确定版本或带本机改动的插件连本体一起打进来 | 通常接近 `lite`，只有被完整打包的那几个 `+` 各自体积 | 带本体的那部分直接装、不用联网；其余按版本装，市场版 | 既要体积小、又要带自定义配置，且个把插件离不开本体 |

`lite` 的两个硬条件：

- 每个插件都得有确定的版本号（`名字@版本` 或本机版本能解析出 `x.y.z`；`0.0.0` 视为没有），否则安装时找不到对应的包；
- 不能有插件选了「自定义配置」——轻量包只记版本、带不走配置与数据，这种情况请改回「插件预设」，或换完整包 / 混合包。

`hybrid` 是**按插件分档**的：能按 `名字@版本` 装的就只记版本（安装时联网取包）；没有确定版本、或打包时选了「连本机改动一起打」的插件，连本体一起打进包里（这部分安装时不用联网，也不依赖 registry）。安装侧不看整包 `format`，只看「包里有没有这个插件的目录」来决定走哪条路——插件内安装与独立安装器是同一套判断。

**完整包的安装优先级（方案 A）**：先按 `名字@版本` 从市场装——profile 依赖写成 `^版本`，插件市场据此显示「市场版」；联网失败或版本不存在才退回包内副本（依赖是 `file:`，市场显示「本地安装」，结果里会明确提示）。这样不手改依赖、不破坏 node_modules 与锁文件，本地改动也不会被市场更新悄悄覆盖。
两者都带 `integrity.json`（sha256）、`security/report.txt` 与不依赖本插件的手工安装说明。

两种包都额外带一个独立安装器 `install/`（`install.mjs` + Windows 的 `install.cmd` + shell 的 `install.sh`），所以**一台干净到只剩 DSH 本体的机器也能装**：

```bash
# 解压后进包目录，任选其一
./install.sh                      # 或双击 install.cmd（Windows）
node install/install.mjs --profile desktop
node install/install.mjs --profile desktop --dry-run      # 只看要做什么
node install/install.mjs --profile desktop --no-bundles   # 装文件但不启用
node install/install.mjs --dsh "「DSH 安装目录」/DeepSeek Harness.exe"  # 指定 DSH 可执行文件
```

安装器对三种策略都适用（`lite`/`hybrid` 按版本取包，`full` 先复制到本机 vendor 再装）。它只依赖 node 与 dsh 命令：先找 `--dsh`/`DSH_CLI`，再找 PATH 里的 `dsh`，最后试常见安装路径；完整版会先把插件复制到 `~/.dsh/dsh-modpack/vendor/<包名>-<短hash>/` 再装（这样解压目录删了也不会断），轻量版按 `name@version` 从 npm 取。装完把 `configs/` 里的条目并进 profile 的 `cordis.patch.yml`，最后提示重启 DSH。它不会自动执行任何包里带的脚本。

目标目录固定是本机的 `~/.dsh`：DSH 的命令行只认自己的家目录（实测不认 `DSH_HOME` / `USERPROFILE`），安装器不去猜别的位置。`--profile` 写一个没建过的名字也行，DSH 会在第一次装插件时自动初始化它。

## 开发

```bash
EXE="/d/大肥鱼/DeepSeek Harness.exe"
# 单测 / 宿主路由 / 联网烟测
ELECTRON_RUN_AS_NODE=1 "$EXE" test/run.mjs
ELECTRON_RUN_AS_NODE=1 "$EXE" test/host-smoke.mjs
ELECTRON_RUN_AS_NODE=1 "$EXE" test/live.mjs
# 改完源码：同步到 profile 副本（file: 依赖是硬链接拷贝，cp 会 EBUSY）并校验
ELECTRON_RUN_AS_NODE=1 "$EXE" dev/tools/sync.cjs
ELECTRON_RUN_AS_NODE=1 "$EXE" dev/tools/verify.cjs
```

本机没有独立的 node：用 `ELECTRON_RUN_AS_NODE=1` 借 DSH 自带的 Node 跑脚本。

`dev/tools/sandbox-e2e.mjs` 是端到端演练：从本机挑一个真实插件打包 → 读回校验 → 装进临时 profile `modpack-sandbox-tmp`（先不启用）→ 断言依赖写入、`bundles` 仍为空、desktop profile 逐字节未变 → 最后删除临时 profile 与临时目录；全程不修改 desktop profile。

`dev/tools/e2e-suite.mjs` 是整套流程自测：随机挑本机 3 个插件（`SEED=xxx` 可复现）→ 打包 full（混合「插件预设 / 自定义配置」）→ 读回校验清单与完整性 → 篡改一个载荷确认会被抓住 → 「有插件」路线用 `installPack` 装进临时 profile → 「无插件」路线解压后跑包内独立安装器（`--no-bundles`）→ 轻量版按版本从 registry 取包再装 → 最后清理 3 个临时 profile、vendor 新目录与临时目录，并用 sha256 确认 desktop 的 `package.json` 与 `cordis.patch.yml` 一字未动。

`dev/tools/risk-e2e.mjs` 专测风险流程：市场查不到的高危包停在 `paused` 可删可确认、市场收录的高危包确认后在同一任务里续跑出包。

装插件优先交给宿主的插件管理器（`pluginManager.installBundle`，和 `dsh plugin add` 同一套 pnpm 实现，失败会自己回滚 `package.json` 与锁文件），管理器不可用或报错时自动退回命令行，两种路径都会写进 `dsh-modpack.log`（`via=manager` / `via=cli`）。

`dev/dsh-refs/` 是官方插件文档的本地参考副本，不参与发布（`files` 里没有 `dev`）。`dev/tools/check-categories.mjs` 只读核对分类分布与「哪些已装插件在市场里有同名条目」。

## 安全检测

- **打包前是强制的，关不掉**：设置与包选项里的开关照常显示，但点击只会弹出一行红字提示（文案为「你想干什么」），五秒后消失；即使直接调用 API 写入 `scanBeforePack: false`，服务端也会强制改回 `true`，`buildPack` 中没有跳过扫描的分支。
- 安装前各一次，静态读文本，不执行任何代码（安装前扫描仍可在设置里关，但默认开）。
- 规则覆盖：私钥、云厂商/代码托管 token、模型 key、Cookie 与会话字段、邮箱/手机号/身份证、内网 IP、本机路径；`curl|sh`、`powershell -enc`、`eval`、可疑长 base64、关闭证书校验、安装脚本等。
- 命中原文不落盘：报告只留规则名、文件、行号与掩码；同一文件同一行同一规则只记一条（一个文件里反复出现的 `exec(` 不会刷成几十行）。
- **高风险一律先停下来等确认**：不论插件能否在本地市场目录里查到，检出高危都停在「等决定」，打包页下方按插件列出命中项；点「我知道在干什么」会在**同一个任务里从检测点接着跑完**（不重新收集、不重复扫描），确认状态写进清单 `security.acknowledged`。不想继续就删掉那条记录，不会在本地留下半成品。
- 目录里能查到的插件，提示语会说明「这批风险来自市场已收录的发行包」；查不到的会提示「这是本机插件，市场里没有对应条目，请自己确认来源」——区别只在措辞与清单里的来源标注，出口是同一条路。
- 轻量包在「下载完、真正安装前」还会对本机刚取下来的代码补扫一遍，高危同样阻断（不是只信清单里那份报告）。
- 包内 `integrity.json` 缺失或清单对不上，一律阻断（要显式 `force`）。
- 解压有体积、压缩比与条目数上限，解压时还按声明长度卡输出（防 zip bomb），拒绝路径逃逸、符号链接、加密条目。
- 只允许 https 与白名单域名下载，逐跳校验重定向。
- 命中按来源分栏：每个插件一组、配置快照一组、数据快照一组，整合包自身的清单与安装器单独一组；整个列表可折叠，每一组也能单独折叠，带高/中/低计数（高危的组排在最前）。
- **配置快照里疑似凭据当场擦掉**：插件选了「自定义配置」时，键名归一化后正好是 `apiKey` / `token` / `secret` / `password` / `cookie` / `sessionKey` 这类字段，值会被替换成字面量 `${REDACTED}`（`apiKeyEnv` 这种「环境变量名」不算，不会被误伤）；值里出现 `sk-`、`ghp_`、`xoxb-`、`AKIA` 这类明文也一并替换。擦了几处、擦在哪个路径会写进配置快照的说明里——导入方要自己重填，包本身不带密钥。

## 离线安装

安装页勾了「离线安装（不联网，直接用包里自带的）」就完全不碰 registry：

- 完整包、混合包里带本体的插件：直接装包内那份（插件市场会显示成本地安装）；
- 只记版本的轻量包（以及混合包里没带本体的插件）：装不了，会在结果里逐条说明「当前没网…联网后再试，或改用完整包」。

没勾时也会先探一次 registry（`/-/ping`，4 秒超时）：探不到就自动按离线走，你什么都不用点。独立安装器同样有 `--offline`。

## 网络：registry 连不上时怎么办

取元数据与 tarball 都走同一层传输（`lib/net.mjs`）：只允许 https、主机必须在允许列表里、重定向逐跳校验、响应体有体积上限。

- **失败会重试**：默认每个请求最多试 2 次（间隔 250ms），默认单次超时 60 秒（慢链路 20 秒连一个 tarball 都下不完）。
- **fetch 不通时用系统 curl 兜底**：个别代理或企业证书环境下，宿主进程的 `fetch` 会报 `fetch failed`，而系统 `curl`（走操作系统证书库）还能通。兜底时同样关掉自动跳转，仍然逐跳校验、仍然有体积上限。
- **设置页可调**：网络超时 5~120 秒（默认 60）、重试 0~5 次、是否允许 curl 兜底；保存后立即生效（不用重启）。
- **版本清单太大也能装**：有的包（例如 `billion-context`）版本清单十几 MB，旧版固定 16 MB 会直接报「下载超过上限」。现在按「精简清单 → 完整清单 → 单版本清单」三层退让，上限默认 64 MB、可在设置页调（4~512）；知道确切版本时直接取 `/名字/版本`，体积最小。
- **传输压缩**：fetch 声明 `accept-encoding: gzip, deflate, br`，curl 兜底走 `--compressed`；慢链路上差别明显。
- **报错会说清楚**：全失败时返回「取不到 <地址>：（各次失败原因）」，而不是一句 `fetch failed`。
## 打没装的插件

搜索框在插件市场目录里查到的条目，**本机没装也能直接勾选打包**：这类条目打的是「市场来源」——打包时按版本从 registry 取包（默认取那一条的当前版本，想钉别的版本就在版本框里写），包内清单记 `source: "npm"`，安装时同样从市场按版本下载。

- 每行最前面的徽标显示当前来源（市场版 / 本机版）；有市场版的默认按市场版勾选；「插件预设 / 自定义配置」对两种来源都可用，默认「插件预设」。
- 没装的插件没有本机代码与配置可打，所以只有「插件预设」一种实质语义（上游原版 + 插件默认配置）。
- 许可证仍按允许列表校验：市场条目的 license 不在列表里时，需要勾「我确认……有权再分发」才会出包。

## 用「打开文件」的方式挑包，或自己挑目录

安装页不再只认插件自己的 `packs` 目录，也不用先知道路径：

- **选择文件…**：安装页有「选择文件…」按钮，弹系统文件选择器（只列 `.dshpack`），选中即读取。
- **浏览文件夹…**：目录那一行有「浏览文件夹…」按钮，弹系统目录选择器；选完目录会自动列目录内容，再勾文件即可。也可以直接在输入框里手写路径，两种方式并存。
- **自己挑目录**：填入任意目录（例如某个下载目录）后点「读这个目录」，列出该目录下的 `.dshpack`；选中后按绝对路径读取。点「回到默认」回到插件自己的 `packs`。
- **已导入的整合包**：用文件选择器或上面的方式读过的包，会留在「已导入的整合包」列表里（最多 8 份同时保留），每张卡片写着打包时的名字、作者、生成时间和描述，可以直接点「选择」切到那一份，或「移除」。列表在内存里，退出程序就清空。
- 读取走的是 `POST /pack/drop`：默认发送原始字节（上限 256 MB）；若环境不允许带二进制体的 POST，界面会自动退回 base64 的 JSON 重发一次，服务端两种格式都接收。目录列举走 `POST /packs { dir }`。两者都不写入磁盘，只有执行安装时才会修改 profile。
- 拖拽已经去掉（外壳自己会接管文件拖放，容易两边都读不到）。

## 安装：也走进度、已装的先跳过、装完再决定换不换

安装现在和打包共用左下角那个进度窗：读包 → 校验完整性 → 扫描 → 逐插件装 → 登记启用清单 → 回填配置，百分比一路走完；任务同样能终止，也能和打包同时跑。

**本机已经装过的插件会先跳过。** 判定按插件名，不按版本——同名的、以及同一个插件但版本不同的，都算「已有」；其余插件照常装完。装完后界面上会列出这些被跳过的插件（本机版本 → 包内版本），给两个选择：

- 直接完成：保留本机那几份，什么都不覆盖；
- 替换为包内版本：只把列出来的那几个换成包内版本（没列出来的不动）。

轻量包（不含插件本体）走的是同一条路：打开时先从 registry 按版本取包，再按上面的规则装。

**联网且插件市场存在同名条目时，优先按市场版本安装。** 这是安装页上的一个开关（默认开启，对应设置项 `preferMarketOnInstall`）：能查到就安装 `名字@版本`，代码来自 registry；查不到、离线、或关闭该开关时，按包内附带的版本安装。每个插件的动作记录都会标明本次走 `market` 还是 `pack`。

**裸 DSH 那一侧**（包里自带的独立安装器）同样默认跳过已装的插件：装的时候它会依次打印「跳过 xxx：本机已装 y」，装完再汇总列出「以下 N 个插件本机已经装了……要换成包内版本，重跑并加 --replace」：

```bash
node install/install.mjs --profile desktop              # 跳过已装的，其余照装
node install/install.mjs --profile desktop --replace    # 本机已装的也换成包内版本
```

## 打包进度与并发

点「打包」后不会卡住页面：任务转到界面的**悬浮窗**（默认在右下角），同一行显示当前在做什么（收集文件 / 读取插件 / 抓配置快照 / 安全检测 / 写入清单 / 压缩）与百分比，下面是进度条。点开悬浮窗能看到每个任务各占一行（标签、状态、进度条），进行中的任务带「终止」按钮；终止只在内存里停下，**不会在本地留下半成品文件**。

任务在安全检测阶段命中高风险时会停在「等决定」，**打包页下方按插件分别列出命中项**（每个插件一组：文件名、行号、规则名、级别，附高/中/低计数）。组内提供「我知道在干什么」：选择后忽略这批风险，在**同一个任务里从检测点继续**——进度不回退、不重新收集文件、不会再次扫描，清单记为 `acknowledged`，红字警告随之撤掉（该记录之后只显示状态与进度）。市场收录的插件与本机插件走同一条路径，仅提示措辞说明风险来源。不作选择时任务保持原位，记录可删除。

- 已收尾的任务右侧提供「删除该进程」，将该条记录从列表移除；进行中的任务只有「终止」。
- 标题栏的「清空进程」一次清除所有收尾记录——完成、失败、取消，以及「超过打包上限」这类中途报错卡住的记录一并带走；进行中的与停在风险点的保留。
- 失败行会以红字显示原因，便于判断是哪个插件体积过大。清空后，打包页上对应的失败提示同时消失。
- 若无响应，说明宿主仍是旧代码；界面会自动改为逐条删除。安装任务无需手动清理：结果写入安装页后会自动从进度窗移除。
- 任务记录默认一直留着（切页签、换入口、关掉面板都不丢），DSH 重启后清空；点「清空进程」随时手动清。设置里把 `jobKeepSeconds` 填成正数才按秒自动清（失败/取消取它与 15 秒的较小值）；失去心跳的 running（十分钟无新进度）先判为失败再收走。
- 「清空进程」采用乐观更新：界面先移除对应行，再通知服务端删除。
- 标题栏的「清空进程」与「收起」不再与拖动、展开争夺同一交互区域：按下这两个按钮只算点击，不触发拖动，也不会切换窗口展开状态。

打包**完成**后，记录上不是「终止」而是「下载安装包」：点它就切回打包页、滚到那次的结果与下载按钮（也可以在结果里选择存到本机 packs 目录）。勾选状态、打包选项与打包结果都放在界面进程的内存里：**切页签、换入口、关掉面板再回来都还在**；页面刷新或 DSH 重启后回到默认。

悬浮窗**按住标题就能拖到任意位置**，松手记住，下次打开还在那儿（存在浏览器本地，和服务端设置无关）；拖到哪都会被限制在窗口内，不会丢到屏幕外。

没有任务时它自己收起，只在原来那个位置留一枚「进度」小按钮；点它就把窗口唤出来。有任务开跑时会自动冒出来，手动「收起」过也会被重新放出来。

打包期间可以继续选插件、改选项、再打一个包——多个任务并行跑，各自独立，互不影响。

体积上限默认 **256 MB**，在设置页按 MB 填，可填 **16~4096**：输入框里存的是草稿文本，点「保存数值」才换算成字节（避免边打边换算越写越大）；超出范围会被夹回，服务端 `clampConfig` 再兜一次底（`maxPackBytes` 16~4096 MB、单文件 1~256 MB、单次下载 16~4096 MB）。这是打包结果的上限；单个下载（一个 tarball 或一份目录索引）另有更紧的 256 MB 上限，避免一次吞下过大的文件。

## 安装与「先不启用」

- 安装走官方 `dsh plugin add`（和插件市场同一条链路）：优先直接起宿主 exe + 内置 `cli.js`，参数不经 `cmd`，所以中文用户名、带空格路径都不会被引号吃掉；找不到才退回 `.cmd`。
- 勾「装好先不启用」时，插件文件与依赖照装，但装完会把 `dsh.profile.bundles` 精确撤回原样 —— 重启也不会加载，想启用再手动加回来。
- 解包前会先清掉 `vendor/<包>/` 里的旧目录，避免上一版残留文件混进新版本。

**它不是杀毒软件**：静态检测会漏也会误报，装第三方插件前仍应自己看来源。

## 配置与数据：怎么带走，怎么放回

打包时抓两类东西，安装时原路放回：

| 内容 | 打包位置 | 安装去哪 |
|---|---|---|
| 补丁层配置（插件选项） | `configs/<name>.json` | 目标 profile 的 `cordis.patch.yml`，按条目 `upsert`：只动目标那一条，其它字节保留 |
| 插件自己的数据文件 | `data/<目录>/…` | 本机 `~/.dsh/<目录>/…`（记忆、词库、笔记这类文本） |

几条硬规矩：

- **配置保真**：嵌套对象、数组、中文与多行字符串都按原结构写回（空数组/空对象写成 `[]`/`{}`；用 JSON 流式写出来的配置也能读回原名）。
- **只擦凭据，不动自定义**：键名归一化后正好等于 `apiKey`/`token`/`secret`/`password`/`cookie` 这类才替换成 `${REDACTED}`，值里出现 `sk-`/`ghp_`/`AKIA` 这类明文也替换；`apiKeyEnv`（环境变量名）、`endpoint`、`model`、`maxTokens`、路径、权重这些原样保留。擦除路径写进说明，导入方自己重填。
- **数据默认不覆盖**：`~/.dsh/<目录>` 下已有同名文件时不动它，安装结果里会写「未覆盖 N 个」；要覆盖就重新装并选择覆盖数据（独立安装器用 `--replace`）。
- **不碰凭证文件**：`credentials.json`、`.env`、`*.pem` 这类文件名在数据快照里直接跳过，并记一条说明。
- **数据快照也擦凭据**：数据文件里出现 `sk-` / `ghp_` / `xoxb-` / `AKIA` 这类明文 token，或 `SESSDATA=…`、`password: …`、`api_key=…` 这种键值对时，只保留键名、值替换成 `${REDACTED}`；正文、路径、普通笔记原样保留。包里记下命中条数，安装结果会提示哪些内容需要重填。
- **裸 DSH 也一样**：包内安装器写配置、写数据用的是同一套规则，不依赖本插件在场。

## 二次开发

- `lib/` 下每个模块都可单独 import：`zip`/`tar` 是通用读写器，`scan` 可接 `extraRules`，`yamlish` 只服务 `cordis.patch.yml`。
- 清单里的 `extensions` 字段打包时原样写入、安装时原样保留，可放自定义数据。
- 设置项 `extraScanRules` 会把额外规则并进扫描器。
- 页面只消费 `/dsh-modpack-kit/api/*`，换 UI 不必改后端。
